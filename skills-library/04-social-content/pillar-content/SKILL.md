# Pillar Content — Hub-and-Cluster Architecture

A specific content architecture for building topical authority: one comprehensive "pillar" page covering a broad topic, surrounded by multiple focused "cluster" pages covering specific subtopics, all interlinked.

## Structure

- **Pillar page** — broad coverage of the core topic, structured so each major section could stand as its own cluster article. Comprehensive but not exhaustively deep on any single subtopic — it's the map, not the destination.
- **Cluster pages** — each goes deep on one specific subtopic referenced in the pillar, targeting a more specific long-tail query.
- **Interlinking (the critical part)** — every cluster page links back to the pillar; the pillar links out to every cluster page. This linking pattern is what signals topical authority to search engines, more than either page type alone.

## Building the architecture

1. Identify the core topic and validate it has enough genuine subtopic depth to support multiple distinct cluster pages (not artificially split filler).
2. Map the subtopics — each should target a genuinely different search intent, not a reworded duplicate of another cluster page.
3. Write the pillar page as a comprehensive overview that naturally references each subtopic, with each reference becoming the internal link anchor to its cluster page.
4. Build cluster pages incrementally — the architecture works even partially complete, unlike programmatic SEO which needs the full dataset to make sense.

## Why this differs from programmatic SEO

Programmatic SEO scales a single template across many similar entities (cities, products). Pillar/cluster architecture goes deep on one subject area across genuinely different subtopics — different tool for a different goal (topical authority vs. long-tail volume capture).
