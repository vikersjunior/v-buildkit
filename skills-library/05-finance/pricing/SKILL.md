# Pricing & Monetization — Packaging Strategy

Structuring how a product is priced and packaged, not just picking a number.

## Step 1: Choose the pricing model that fits the value delivery

- **Flat/subscription** — predictable value delivered continuously (most SaaS).
- **Usage-based** — value scales directly with consumption (API calls, transactions, storage) — fits when usage correlates with the customer's own realized value.
- **Per-seat** — value scales with number of users accessing it — fits collaborative tools, breaks down for tools with high per-user variance in usage intensity.
- **Transaction/commission-based** — fits marketplaces and platforms where the product's value is directly tied to facilitating a transaction (relevant for commerce/logistics platforms).
- **Freemium** — fits products with strong viral/network effects where free-tier users create value for paid users, or where the free tier functions as a genuine acquisition funnel toward a clear upgrade trigger.

## Step 2: Design tiers around genuine value segments, not arbitrary feature splits

Each tier should map to a distinct customer segment's actual willingness-to-pay driver, not a random assortment of features. Common structure: a low/free tier for acquisition and habit formation, a mid tier that captures the majority of the customer base at the core value prop, a high tier for power users/teams with premium needs (advanced features, higher usage caps, dedicated support).

## Step 3: Set price points with reference to willingness-to-pay evidence

Anchor price points against: competitor pricing for comparable value delivered, value-based estimation (what economic value does this create for the customer, price as a fraction of that), and if available, direct willingness-to-pay research (surveys, pricing experiments) rather than pure gut-feel.

## Step 4: Design the upgrade path deliberately

Identify the specific trigger (a usage cap hit, a feature gate encountered) that should prompt upgrade consideration, and make that moment visible to the user rather than a passive limit with no clear next step.

## Ghana/African-market note

Local purchasing power and payment-method access (Mobile Money vs. card) often require a genuinely different price point and billing cadence (e.g. shorter billing cycles matching income patterns) than a direct currency-converted transplant of a Western price point — don't just apply an FX conversion to a US/EU price and call it localized pricing.
